📊 Aggregieren – GROUP BY · HAVING

SELECT p.product_name, SUM(l.quantity) AS units_sold
FROM silver.sales_order_line AS l
INNER JOIN silver.product AS p
    ON l.product_id = p.product_id
WHERE l.quantity > 0           -- Zeilen: vorher
GROUP BY p.product_name
HAVING SUM(l.quantity) < 5000  -- Gruppen: danach

Übrige Spalten gehören in GROUP BY (oder GROUP BY ALL). Aggregate ignorieren NULLs.

COUNT(DISTINCT order_id)
    FILTER (WHERE sales_channel = 'Online')   AS online,
SUM(gross_revenue_eur)
    FILTER (WHERE sales_channel = 'In-store') AS cafe

FILTER (WHERE …): mehrere bedingte KPIs in einem Durchlauf.

➕ Zwischensummen – ROLLUP · CUBE

SELECT s.store_name, p.product_category,
       SUM(f.gross_revenue_eur)     AS revenue_eur,
       GROUPING(p.product_category) AS is_store_total
FROM gold.fact_coffee_sales AS f
INNER JOIN gold.dim_store AS s
    ON f.store_key = s.store_key
INNER JOIN gold.dim_product AS p
    ON f.product_key = p.product_key
GROUP BY ROLLUP (s.store_name, p.product_category)

ROLLUP (a, b) → (a, b) · (a) · gesamt  |  CUBE (a, b) → (a, b) · (a) · (b) · gesamt  |  GROUPING(col) = 1: dieses NULL heißt „alle Werte“.

🔗 Joins – Spalten aus mehreren Tabellen verknüpfen

INNER JOIN
nur Zeilen mit Partner auf beiden Seiten		Bestellpositionen × Produkte – unbekannte SKUs fallen weg
LEFT JOIN
alle linken Zeilen; NULL, wo kein Partner		Verkäufe × Kundenkarten – Gäste bleiben im Fakt
FULL OUTER JOIN
alles von beiden Seiten		CRM × Kundenkonten – nur Café, nur online, beides
LEFT SEMI JOIN
linke Zeilen mit Treffer – nur linke Spalten, nie doppelt		Positionen abgeschlossener Bestellungen · = WHERE EXISTS
LEFT ANTI JOIN
linke Zeilen ohne Treffer		Positionen stornierter Bons, Mitglieder ohne Kauf · = NOT EXISTS
CROSS JOIN
jede Kombination, kein ON		Filiale × Tag – Tage ohne Umsatz finden
FROM silver.sales_order_line AS l
INNER JOIN silver.sales_order AS o
    ON l.order_id = o.order_id
LEFT JOIN silver.product_price AS pp    -- Range Join: der Preis,
    ON  l.product_id = pp.product_id    -- der am Bestelltag gilt
    AND o.order_date BETWEEN pp.valid_from
        AND COALESCE(pp.valid_to, DATE'9999-12-31')

🧯 Join-Stolperfallen

  1. Still verlorene Zeilen – ein INNER JOIN verwirft Zeilen ohne Partner. COUNT(*) vorher und nachher vergleichen.
  2. Unsaubere Schlüssel – Groß-/Kleinschreibung, Leerzeichen, Typen. Erst normalisieren: LOWER(TRIM(email)), CAST(id AS INT). NULL-Schlüssel finden nie einen Partner.
  3. Fan-out – mehrere Zeilen pro Schlüssel rechts vervielfachen die linken Zeilen (und verdoppeln den Umsatz). Rechte Seite erst eindeutig machen (QUALIFY, GROUP BY).
  4. LEFT JOIN wird zum INNER JOIN – eine WHERE-Bedingung auf die rechte Tabelle entfernt die NULL-Zeilen wieder. Sie gehört ins ON.

✅ Den Gold Layer prüfen

-- ① der Primärschlüssel ist eindeutig          → 0 Zeilen
SELECT customer_key FROM gold.dim_customer
GROUP BY customer_key HAVING COUNT(*) > 1;
-- ② jede Faktzeile findet ihre Dimensionszeile → 0 Zeilen
SELECT * FROM gold.fact_coffee_sales AS f
LEFT ANTI JOIN gold.dim_customer AS d
    ON f.customer_key = d.customer_key;
-- ③ nichts verloren: die Summen stimmen         → gleich
SELECT SUM(quantity)      FROM silver.sales_order_line;
SELECT SUM(quantity_sold) FROM gold.fact_coffee_sales;
-- ④ neue = alte Tabelle, in beide Richtungen   → 0 Zeilen
SELECT * FROM new_table MINUS SELECT * FROM old_table;
SELECT * FROM old_table MINUS SELECT * FROM new_table;

🧱 WITH … AS – Bausteine benennen

WITH active_card AS (
    SELECT customer_id, loyalty_tier
    FROM silver.loyalty_card
    WHERE is_active
),
orders AS (
    SELECT customer_key, COUNT(DISTINCT order_id) AS n
    FROM gold.fact_coffee_sales
    GROUP BY customer_key

SELECT c.customer_id, a.loyalty_tier, o.n AS orders
FROM silver.customer AS c
LEFT JOIN active_card AS a
    ON c.customer_id = a.customer_id
LEFT JOIN orders AS o
    ON c.customer_id = o.customer_key

🌳 WITH RECURSIVE – Hierarchien

WITH RECURSIVE org (employee_id, full_name, level) AS (
    SELECT employee_id, full_name, 1      -- ① Anker
    FROM silver.employee
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.employee_id, e.full_name, o.level + 1  -- ②
    FROM silver.employee AS e
    INNER JOIN org AS o ON e.manager_id = o.employee_id
)
SELECT * FROM org ORDER BY level

Endet, sobald ein Schritt keine neuen Zeilen findet. Kleine, feste Tiefe? Dann reichen Self-Joins.

🪟 Window-Funktionen – auf andere Zeilen schauen

FUNCTION(…) OVER (PARTITION BY <Gruppe> ORDER BY <Sortierung>)
ROW_NUMBER()1, 2, 3 … pro Partition – Duplikate, „erste Bestellung“
RANK() · DENSE_RANK()Ränge mit Gleichstand (1, 1, 3 · 1, 1, 2)
SUM(x) OVER (PARTITION BY g)Gruppensumme neben jeder Zeile
SUM(x) OVER (… ORDER BY d)laufende Summe
LAG(x) · LEAD(x)Wert der vorherigen · nächsten Zeile
SELECT *                         -- neueste CRM-Version
FROM bronze.crm_customers
QUALIFY ROW_NUMBER() OVER (PARTITION BY customer_id
                           ORDER BY updated_at DESC) = 1

Anders als GROUP BY behalten Window-Funktionen jede Zeile. QUALIFY filtert darauf – wie HAVING auf Aggregate.

🧰 Funktionen für den Gold Layer

EXPLODE · POSEXPLODE eine Zeile pro Array-Element (+ Position)
SELECT order_id, POSEXPLODE(items) AS (item_pos, item)
FROM bronze.web_orders

EXPLODE(SEQUENCE(d1, d2, INTERVAL 1 DAY)) = eine Zeile pro Tag · leere Arrays verschwinden → EXPLODE_OUTER

COALESCE der erste Wert, der nicht NULL ist
COALESCE(lc.customer_id, wc.customer_id, -1) AS customer_key,
COALESCE(discount_eur, 0)                     AS discount_eur

Standardwerte und „die erste Quelle, die es weiß“

CASE · IFF Regeln – das erste wahre WHEN gewinnt
CASE WHEN total_orders = 0    THEN 'Prospect'
     WHEN total_orders >= 100 THEN 'Loyalist'
     WHEN total_orders >= 10  THEN 'Regular'
     ELSE 'Occasional' END,
IFF(is_online, 'Online', 'In-store')

ohne ELSE → NULL · IFF für genau zwei Ergebnisse

DECODE Codes übersetzen – ein kompaktes Lookup-CASE
DECODE(payment_code, 'B', 'Cash', 'G', 'Girocard',
                    'K', 'Credit Card', 'Unknown')

immer einen Standardwert angeben – neue Codes bleiben sichtbar

MAX_BY · MIN_BY der Wert am Maximum / Minimum
MAX_BY(list_price_eur, valid_from) AS current_price,
MAX_BY(store_key, orders)          AS favourite_store_key

„neueste“, „aktuelle“, „Lieblings-…“ – ohne Self-Join

DATEADD · DATEDIFF mit Datumswerten rechnen
CAST(DATEADD(DAY, -1, next_valid_from) AS DATE) AS valid_to,
DATEDIFF(DAY, last_purchase_date, current_date()) AS idle

DATEADD liefert einen TIMESTAMP → nach DATE casten · Monatsenden passen (31.1. + 1 Monat = 28.2.)
